
# 42.ALTER TABLE

---

## 📌 What is ALTER TABLE

> **ALTER TABLE** is a DDL command used to **modify the structure of an existing table**
> without deleting the table or losing its data.

You use `ALTER TABLE` when:

- You forgot to add a column when creating the table
- You need to change a column's data type
- You want to add or remove a constraint
- You need to rename a column
- You want to add a default value to a column

```
CREATE TABLE → builds the table structure (done once)
ALTER TABLE  → changes that structure later (done anytime)

Your data stays safe — ALTER only changes structure, not rows.
```

---

## 📌 ALTER TABLE Operations — Overview

```
ALTER TABLE TableName
    │
    ├── ADD          → add a new column
    ├── DROP COLUMN  → remove a column
    ├── ALTER COLUMN → change data type or nullability
    ├── ADD CONSTRAINT    → add PK, FK, UNIQUE, CHECK, DEFAULT
    └── DROP CONSTRAINT   → remove a constraint
```

---

## 📌 1. ADD — Adding a New Column

```sql
-- Syntax
ALTER TABLE TableName
ADD ColumnName DataType [Constraints];

-- Examples

-- Add a simple column
ALTER TABLE Users
ADD Email NVARCHAR(100);

-- Add a column with NOT NULL and DEFAULT
ALTER TABLE Users
ADD IsActive BIT NOT NULL DEFAULT 1;

-- Add a column with DEFAULT value
ALTER TABLE Users
ADD CreatedAt DATETIME2 DEFAULT GETDATE();

-- Add multiple columns at once
ALTER TABLE Users
ADD
    PhoneNumber NVARCHAR(15),
    LastLoginAt DATETIME2,
    Department  NVARCHAR(50) DEFAULT 'General';
```

> ⚠️ **Important:** If you add a `NOT NULL` column to a table that already has rows,
> you MUST provide a `DEFAULT` value. Otherwise SQL Server throws an error
> because existing rows would have NULL in that column.

```sql
-- ❌ WILL FAIL if table already has data
ALTER TABLE Users
ADD Age INT NOT NULL;

-- ✅ CORRECT — provide a default
ALTER TABLE Users
ADD Age INT NOT NULL DEFAULT 0;
```

---

## 📌 2. DROP COLUMN — Removing a Column

```sql
-- Syntax
ALTER TABLE TableName
DROP COLUMN ColumnName;

-- Example
ALTER TABLE Users
DROP COLUMN PhoneNumber;

-- Drop multiple columns at once
ALTER TABLE Users
DROP COLUMN PhoneNumber, Department;
```

> ⚠️ **Rules for DROP COLUMN:**
>
> - Cannot drop a column that is part of a PRIMARY KEY
> - Cannot drop a column that has a FOREIGN KEY reference
> - Cannot drop a column that is used in an INDEX
> - You must drop the constraint/index first, then drop the column

```sql
-- ❌ WILL FAIL if column has a constraint
ALTER TABLE Users
DROP COLUMN Email;

-- ✅ Drop constraint first, then drop the column
ALTER TABLE Users
DROP CONSTRAINT UQ_Users_Email;   -- drop the unique constraint

ALTER TABLE Users
DROP COLUMN Email;                 -- now safe to drop
```

---

## 📌 3. ALTER COLUMN — Changing a Column's Data Type or Nullability

```sql
-- Syntax
ALTER TABLE TableName
ALTER COLUMN ColumnName NewDataType [NULL | NOT NULL];

-- Change data type size
ALTER TABLE Users
ALTER COLUMN Email NVARCHAR(200);   -- was 100, now 200

-- Change from NULL to NOT NULL (column must have no NULLs in data first)
ALTER TABLE Users
ALTER COLUMN Email NVARCHAR(200) NOT NULL;

-- Change from NOT NULL to NULL (allow empty values)
ALTER TABLE Users
ALTER COLUMN PhoneNumber NVARCHAR(15) NULL;
```

> ⚠️ **Rules for ALTER COLUMN:**
>
> - Cannot change data type if a computed column depends on it
> - Cannot change to NOT NULL if any existing row has NULL in that column
> - Cannot change type of a column that is part of an INDEX (drop index first)

```sql
-- If column has NULLs, fill them first before changing to NOT NULL
UPDATE Users SET Email = 'unknown@example.com' WHERE Email IS NULL;

-- Now safe to alter
ALTER TABLE Users
ALTER COLUMN Email NVARCHAR(200) NOT NULL;
```

## 📌 4. ADD CONSTRAINT — Adding Constraints After Table Creation

```sql
-- Add PRIMARY KEY
ALTER TABLE Orders
ADD CONSTRAINT PK_Orders PRIMARY KEY (OrderId);

-- Add FOREIGN KEY
ALTER TABLE Orders
ADD CONSTRAINT FK_Orders_Users
    FOREIGN KEY (UserId) REFERENCES Users(UserId);

-- Add UNIQUE constraint
ALTER TABLE Users
ADD CONSTRAINT UQ_Users_Email UNIQUE (Email);

-- Add CHECK constraint
ALTER TABLE Users
ADD CONSTRAINT CHK_Age CHECK (Age >= 18 AND Age <= 100);

-- Add DEFAULT constraint
ALTER TABLE Users
ADD CONSTRAINT DF_Users_Role DEFAULT 'User' FOR Role;
```

---

## 📌 5. DROP CONSTRAINT — Removing a Constraint

```sql
-- Syntax
ALTER TABLE TableName
DROP CONSTRAINT ConstraintName;

-- Examples
ALTER TABLE Users
DROP CONSTRAINT UQ_Users_Email;    -- remove unique constraint

ALTER TABLE Orders
DROP CONSTRAINT FK_Orders_Users;   -- remove foreign key

ALTER TABLE Users
DROP CONSTRAINT CHK_Age;           -- remove check constraint
```

> 💡 To find constraint names (if you forgot):
>
> ```sql
> SELECT CONSTRAINT_NAME, CONSTRAINT_TYPE
> FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS
> WHERE TABLE_NAME = 'Users';
> ```

## 📌 6. RENAME — Renaming a Column

> SQL Server does NOT have `ALTER TABLE ... RENAME COLUMN` syntax directly.
> Use the system stored procedure `sp_rename`.

```sql
-- Syntax
EXEC sp_rename 'TableName.OldColumnName', 'NewColumnName', 'COLUMN';

-- Example: rename 'UserId' to 'UserCode'
EXEC sp_rename 'Users.UserId', 'UserCode', 'COLUMN';

-- Rename a table itself
EXEC sp_rename 'OldTableName', 'NewTableName';
```

## 📌 Real-World Example — Building the Users Table Step by Step

This is a realistic scenario — you create the table, then realise you need more columns.

```sql
-- Day 1: Create the basic table
CREATE TABLE Users
(
    UserId       NVARCHAR(50) PRIMARY KEY,
    PasswordHash NVARCHAR(255) NOT NULL
);

-- Day 2: Need to track roles
ALTER TABLE Users
ADD Role NVARCHAR(20) NOT NULL DEFAULT 'User';

-- Day 3: Need to track login failures
ALTER TABLE Users
ADD FailedAttempts INT NOT NULL DEFAULT 0;

ALTER TABLE Users
ADD IsLocked BIT NOT NULL DEFAULT 0;

-- Day 4: Need email for password reset
ALTER TABLE Users
ADD Email NVARCHAR(100) NULL;        -- nullable first (existing rows have no email)

-- Later: made email mandatory after filling all rows
UPDATE Users SET Email = 'unknown@example.com' WHERE Email IS NULL;

ALTER TABLE Users
ALTER COLUMN Email NVARCHAR(100) NOT NULL;

-- Add unique constraint on email
ALTER TABLE Users
ADD CONSTRAINT UQ_Users_Email UNIQUE (Email);

-- Day 5: Rename PasswordHash to PwdHash (company standard)
EXEC sp_rename 'Users.PasswordHash', 'PwdHash', 'COLUMN';

-- Final table:
SP_HELP Users;
```

## ❓ Interview Questions

**Q: What is ALTER TABLE used for?**
A: To modify the structure of an existing table — add/remove columns, change data types, add/remove constraints — without losing existing data.

**Q: Can you add a NOT NULL column to a table that has existing rows?**
A: Yes, but only if you provide a DEFAULT value. Otherwise existing rows would have NULL in the new column, which violates NOT NULL.

**Q: How do you rename a column in SQL Server?**
A: SQL Server doesn't have a direct `RENAME COLUMN` syntax. Use:
`EXEC sp_rename 'TableName.OldName', 'NewName', 'COLUMN';`

**Q: What is the difference between DROP TABLE and ALTER TABLE DROP COLUMN?**

|            | DROP TABLE                      | ALTER TABLE DROP COLUMN       |
| ---------- | ------------------------------- | ----------------------------- |
| Effect     | Removes entire table + all data | Removes one column from table |
| Data lost  | All rows and structure          | Only that column's data       |
| Reversible | No                              | No                            |
