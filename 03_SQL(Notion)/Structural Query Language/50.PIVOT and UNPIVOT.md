
# 50.PIVOT and UNPIVOT

---

## 📌 What is PIVOT

> **PIVOT** rotates data from **rows into columns** — turning distinct
> values in one column into separate column headers, with aggregated
> values underneath.

```
BEFORE PIVOT (rows):                AFTER PIVOT (columns):
──────────────────────              ──────────────────────────────
Dept | Month | Sales                Dept | Jan  | Feb  | Mar
IT   | Jan   | 1000                 IT   | 1000 | 1200 | 900
IT   | Feb   | 1200                 HR   | 500  | 600  | 700
IT   | Mar   | 900
HR   | Jan   | 500
HR   | Feb   | 600
HR   | Mar   | 700
```

> Think of it like an Excel Pivot Table — "Month" values become
> column headers, "Sales" gets aggregated (usually SUM) under each one.

---

## 📌 PIVOT Syntax

```sql
SELECT PivotColumn, [Value1], [Value2], [Value3]
FROM
(
    SELECT SourceColumn1, SourceColumn2, SourceColumn3
    FROM SourceTable
) AS SourceQuery
PIVOT
(
    AGG_FUNC(SourceColumn3)
    FOR SourceColumn2 IN ([Value1], [Value2], [Value3])
) AS PivotTableAlias;
```

| Part                           | Meaning                                                                     |
| ------------------------------ | --------------------------------------------------------------------------- |
| Inner`SELECT`                | Only pull the columns PIVOT actually needs                                  |
| `AGG_FUNC(...)`              | How to aggregate when multiple rows collapse into one cell                  |
| `FOR SourceColumn2`          | The column whose**values** become new **column headers**        |
| `IN ([Value1], [Value2]...)` | The exact values to turn into columns — must be**listed explicitly** |

## 📌 Real Example — Sales by Department and Month

```sql
-- Source data: Sales table with Department, MonthName, Amount

SELECT Department, [Jan], [Feb], [Mar]
FROM
(
    SELECT Department, MonthName, Amount
    FROM Sales
) AS SourceData
PIVOT
(
    SUM(Amount)
    FOR MonthName IN ([Jan], [Feb], [Mar])
) AS PivotResult;
```

**Result:**

```
Department | Jan  | Feb  | Mar
IT         | 1000 | 1200 | 900
HR         | 500  | 600  | 700
```

> ⚠️ **The values in `IN (...)` must be known and written out explicitly**
> at query-writing time — PIVOT can't dynamically discover new column
> values on its own. If a new month (`Apr`) appears in the data, the
> query must be manually updated to include `[Apr]`.

---

## 📌 Real-World Example — Login Attempts by Status per User

```sql
SELECT UserId, [Success], [Failed], [Locked]
FROM
(
    SELECT UserId, Status
    FROM LoginAttempts
) AS SourceData
PIVOT
(
    COUNT(Status)
    FOR Status IN ([Success], [Failed], [Locked])
) AS PivotResult;
```

```
UserId | Success | Failed | Locked
sumit  | 15      | 2      | 0
rahul  | 8        | 5      | 1
```

## 📌 Dynamic PIVOT — When You Don't Know the Columns in Advance

> Since `IN (...)` needs a hardcoded list, use **dynamic SQL** to build
> the column list at runtime when the values can change (e.g. months,
> product names that grow over time).

```sql
DECLARE @Columns NVARCHAR(MAX);
DECLARE @SQL NVARCHAR(MAX);

-- Step 1: build the column list dynamically from actual data
SELECT @Columns = STRING_AGG(QUOTENAME(MonthName), ',')
FROM (SELECT DISTINCT MonthName FROM Sales) AS M;

-- Step 2: build and run the dynamic PIVOT query
SET @SQL = N'
SELECT Department, ' + @Columns + N'
FROM
(
    SELECT Department, MonthName, Amount FROM Sales
) AS SourceData
PIVOT
(
    SUM(Amount) FOR MonthName IN (' + @Columns + N')
) AS PivotResult;';

EXEC sp_executesql @SQL;
```

> `QUOTENAME()` wraps each value in `[brackets]` safely (handles spaces/
> special characters). `STRING_AGG` joins them with commas.

## 📌 What is UNPIVOT

> **UNPIVOT** does the opposite of PIVOT — it rotates **columns back
> into rows**. Useful when data is stored "wide" but you need it "long"
> (e.g. for charting, or normalizing a badly-designed table).

```
BEFORE UNPIVOT (columns):           AFTER UNPIVOT (rows):
──────────────────────────          ──────────────────────
Dept | Jan  | Feb  | Mar            Dept | MonthName | Amount
IT   | 1000 | 1200 | 900            IT   | Jan       | 1000
HR   | 500  | 600  | 700            IT   | Feb       | 1200
                                     IT   | Mar       | 900
                                     HR   | Jan       | 500
                                     HR   | Feb       | 600
                                     HR   | Mar       | 700
```

---

## 📌 UNPIVOT Syntax

```sql
SELECT Department, MonthName, Amount
FROM
(
    SELECT Department, [Jan], [Feb], [Mar]
    FROM SalesPivoted
) AS SourceData
UNPIVOT
(
    Amount FOR MonthName IN ([Jan], [Feb], [Mar])
) AS UnpivotResult;
```

| Part                         | Meaning                                                        |
| ---------------------------- | -------------------------------------------------------------- |
| `Amount`                   | New column name that will hold the**values**             |
| `FOR MonthName`            | New column name that will hold the**old column headers** |
| `IN ([Jan], [Feb], [Mar])` | Which existing columns to unpivot                              |

---

## 📌 Real-World Example — Normalizing a Wide Survey Table

```sql
-- Source: SurveyResults with separate columns per question (bad design)
-- UserId | Q1_Rating | Q2_Rating | Q3_Rating

SELECT UserId, Question, Rating
FROM
(
    SELECT UserId, Q1_Rating, Q2_Rating, Q3_Rating
    FROM SurveyResults
) AS SourceData
UNPIVOT
(
    Rating FOR Question IN (Q1_Rating, Q2_Rating, Q3_Rating)
) AS UnpivotResult;
```

```
UserId | Question   | Rating
u1     | Q1_Rating  | 4
u1     | Q2_Rating  | 5
u1     | Q3_Rating  | 3
```

> This "long" format is much easier to `GROUP BY Question` or feed
> into charting tools than the wide, column-per-question original.

## 📌 PIVOT vs UNPIVOT — Side by Side

|                                   | PIVOT                                      | UNPIVOT                                           |
| --------------------------------- | ------------------------------------------ | ------------------------------------------------- |
| Direction                         | Rows → Columns                            | Columns → Rows                                   |
| Needs an aggregate function       | ✅ Yes (SUM, COUNT, etc.)                  | ❌ No                                             |
| Common use                        | Reports, dashboards, Excel-style summaries | Normalizing wide tables, prepping data for charts |
| Column list must be known upfront | ✅ Yes (or use dynamic SQL)                | ✅ Yes (list of source columns)                   |

## 📌 GROUP BY + CASE — The Manual Alternative to PIVOT

> Before knowing PIVOT syntax, this conditional aggregation pattern
> achieves the same result and is worth recognizing:

```sql
-- Same result as the PIVOT example above, written manually
SELECT
    Department,
    SUM(CASE WHEN MonthName = 'Jan' THEN Amount ELSE 0 END) AS Jan,
    SUM(CASE WHEN MonthName = 'Feb' THEN Amount ELSE 0 END) AS Feb,
    SUM(CASE WHEN MonthName = 'Mar' THEN Amount ELSE 0 END) AS Mar
FROM Sales
GROUP BY Department;
```

> Functionally identical to PIVOT — some developers prefer this because
> it's more flexible (can mix multiple aggregate types) even though
> PIVOT syntax is more concise for simple cases.

## ❓ Interview Questions

**Q: What does PIVOT do, and why does it need an aggregate function?**
A: PIVOT rotates distinct row values into column headers. It needs an aggregate function (SUM, COUNT, etc.) because multiple source rows might map to the same new row/column intersection, and SQL needs a rule for combining them into one cell.

**Q: Can PIVOT automatically detect new column values as data changes?**
A: No — the values listed in the `IN (...)` clause must be written explicitly at query time. To handle values that aren't known in advance, dynamic SQL is used to build the column list from the data at runtime.

**Q: What is UNPIVOT typically used for?**
A: Converting "wide" tables (one column per category) back into "long"/normalized row format — commonly needed when preparing data for charting tools, further aggregation, or fixing a poorly normalized table design.

**Q: What's an alternative to PIVOT that doesn't require the PIVOT keyword?**
A: Conditional aggregation using `SUM(CASE WHEN Col = 'X' THEN Value ELSE 0 END)` per desired column, combined with GROUP BY — produces the same result and is sometimes preferred for its flexibility.
