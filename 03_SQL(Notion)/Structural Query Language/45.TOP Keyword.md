
# 45.TOP Keyword

---

## 📌 What is TOP

> **TOP** limits the number (or percentage) of rows returned by a query.
> It's a **SQL Server-specific** feature (Standard SQL uses `LIMIT`/`FETCH` instead).

```
SELECT * FROM Users;          → returns ALL rows
SELECT TOP 10 * FROM Users;   → returns only the FIRST 10 rows
```

> ⚠️ **TOP without ORDER BY gives unpredictable rows** — SQL Server picks
> whichever 10 rows it feels like based on physical storage order, which
> can change. **Always pair TOP with ORDER BY** for consistent results.

---

## 📌 Basic Syntax

```sql
SELECT TOP (n) column1, column2
FROM TableName
ORDER BY column1;
```

```sql
-- Get the 5 most recently created users
SELECT TOP 5 UserId, CreatedAt
FROM Users
ORDER BY CreatedAt DESC;

-- Parentheses around N are optional but recommended
SELECT TOP (5) * FROM Users ORDER BY CreatedAt DESC;
```

---

## 📌 TOP with PERCENT

```sql
-- Get the top 10% of rows (rounded up)
SELECT TOP 10 PERCENT *
FROM Users
ORDER BY CreatedAt DESC;
```

- If the table has 95 rows, `TOP 10 PERCENT` returns **10** rows (rounds up)
- Must still be paired with `ORDER BY` for meaningful results

---

## 📌 TOP with WITH TIES

> `WITH TIES` includes **extra rows** that tie with the last row in the result,
> based on the `ORDER BY` column.

```sql
-- If multiple users have the SAME CreatedAt as the 5th row,
-- include them too (result could be more than 5 rows)
SELECT TOP 5 WITH TIES UserId, CreatedAt
FROM Users
ORDER BY CreatedAt DESC;
```

| Without WITH TIES                                                        | With WITH TIES                                        |
| ------------------------------------------------------------------------ | ----------------------------------------------------- |
| Exactly N rows, even if row N+1 ties with row N                          | N or more rows — all ties with the last row included |
| `WITH TIES` **requires** `ORDER BY` — mandatory, not optional |                                                       |

```sql
-- ❌ WILL FAIL — WITH TIES needs ORDER BY
SELECT TOP 5 WITH TIES * FROM Users;

-- ✅ CORRECT
SELECT TOP 5 WITH TIES * FROM Users ORDER BY CreatedAt DESC;
```

---

## 📌 TOP with a Variable

```sql
DECLARE @RowLimit INT = 3;

SELECT TOP (@RowLimit) UserId, Role
FROM Users
ORDER BY CreatedAt DESC;
```

> Useful in stored procedures where the row limit is a parameter passed in.

---

## 📌 TOP in UPDATE / DELETE — Not Just SELECT

TOP isn't limited to SELECT — it works on UPDATE and DELETE too:

```sql
-- Lock the OLDEST 10 unresolved failed login attempts
UPDATE TOP (10) LoginAttempts
SET Status = 'Reviewed'
WHERE Status = 'Pending';

-- Delete the oldest 100 log rows (batch cleanup — common for large tables)
DELETE TOP (100) FROM AuditLog
WHERE CreatedAt < DATEADD(YEAR, -2, GETDATE());
```

> ⚠️ **TOP in UPDATE/DELETE has no ORDER BY support** — SQL Server doesn't
> let you order which rows get updated/deleted this way. If you need a
> specific order, combine with a CTE (see below).

```sql
-- ✅ Ordered DELETE using CTE + TOP — common batch-cleanup pattern
WITH OldestLogs AS (
    SELECT TOP (100) *
    FROM AuditLog
    ORDER BY CreatedAt ASC
)
DELETE FROM OldestLogs;
```

## 📌 TOP vs OFFSET-FETCH (Pagination)

> `TOP` alone can't **skip** rows — it only gets the first N.
> For pagination (page 2, page 3...), use `OFFSET ... FETCH` instead.

```sql
-- TOP: always gets rows 1-10, can't get rows 11-20
SELECT TOP 10 * FROM Users ORDER BY CreatedAt DESC;

-- OFFSET-FETCH: true pagination — skip then take
SELECT UserId, CreatedAt
FROM Users
ORDER BY CreatedAt DESC
OFFSET 10 ROWS FETCH NEXT 10 ROWS ONLY;   -- page 2 (skip 10, get next 10)
```

|                                   | TOP                        | OFFSET-FETCH                      |
| --------------------------------- | -------------------------- | --------------------------------- |
| Skip rows                         | ❌ Cannot                  | ✅`OFFSET n ROWS`               |
| Needs ORDER BY                    | Recommended                | ✅ Mandatory                      |
| Use for                           | "Give me the first/best N" | Real pagination (page 1, 2, 3...) |
| Works in older SQL Server (2008-) | ✅ Yes                     | ❌ Only 2012+                     |

```sql
-- Full pagination example — Page 3, 20 rows per page
DECLARE @PageNumber INT = 3;
DECLARE @PageSize INT = 20;

SELECT UserId, Email, CreatedAt
FROM Users
ORDER BY CreatedAt DESC
OFFSET (@PageNumber - 1) * @PageSize ROWS
FETCH NEXT @PageSize ROWS ONLY;
```

## 📌 Real-World Examples

```sql
-- Top 3 highest failed-attempt users (security review)
SELECT TOP 3 UserId, FailedAttempts
FROM Users
ORDER BY FailedAttempts DESC;

-- Most recent 1 login (last login check)
SELECT TOP 1 UserId, LoginTime
FROM LoginAttempts
WHERE UserId = 'sumit'
ORDER BY LoginTime DESC;

-- Grid pagination in a Kendo UI grid — page 2, 25 rows per page
SELECT UserId, Role, Email
FROM Users
ORDER BY UserId
OFFSET 25 ROWS FETCH NEXT 25 ROWS ONLY;
```

## 📌 Quick Reference

| Goal                          | Syntax                                                |
| ----------------------------- | ----------------------------------------------------- |
| First N rows                  | `SELECT TOP (N) * FROM T ORDER BY Col`              |
| Top N% of rows                | `SELECT TOP N PERCENT * FROM T ORDER BY Col`        |
| Include ties at the boundary  | `SELECT TOP N WITH TIES * FROM T ORDER BY Col`      |
| N from a variable             | `SELECT TOP (@N) * FROM T ORDER BY Col`             |
| Limit rows in UPDATE          | `UPDATE TOP (N) T SET ...`                          |
| Limit rows in DELETE          | `DELETE TOP (N) FROM T`                             |
| True pagination (skip + take) | `ORDER BY Col OFFSET x ROWS FETCH NEXT y ROWS ONLY` |

## ❓ Interview Questions

**Q: What's the difference between TOP and OFFSET-FETCH?**
A: `TOP` only returns the first N rows and cannot skip rows, so it can't do pagination on its own. `OFFSET-FETCH` can skip a number of rows before returning the next batch, making it the standard way to implement pagination.

**Q: Why should TOP always be used with ORDER BY?**
A: Without ORDER BY, SQL Server has no defined rule for which rows count as the "top" ones — it just returns whatever rows come first based on internal storage/execution, which isn't guaranteed to be consistent between runs.

**Q: What does WITH TIES do, and what's required to use it?**
A: It includes any additional rows that tie with the value in the last row of the TOP result, based on the ORDER BY column. It requires an ORDER BY clause — without one, SQL Server throws an error.

**Q: Can you use ORDER BY directly with `DELETE TOP (N)`?**
A: No — `DELETE TOP` doesn't support ORDER BY directly. To delete a specific ordered set of rows, wrap the query in a CTE that does the ordering, then DELETE FROM the CTE.
