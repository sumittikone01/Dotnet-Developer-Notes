# 46.ROLLUP and CUBE

---

## 📌 What Problem These Solve

> Normal `GROUP BY` gives you totals for **each group**, but not
> **subtotals** or a **grand total** in the same result set.
> `ROLLUP` and `CUBE` extend `GROUP BY` to add those automatically.

```
Plain GROUP BY:
──────────────────────────
Department | Role   | TotalSalary
IT         | Admin  | 50000
IT         | User   | 30000
HR         | Admin  | 40000
→ No subtotal per Department, no grand total

WITH ROLLUP:
──────────────────────────
Department | Role   | TotalSalary
IT         | Admin  | 50000
IT         | User   | 30000
IT         | NULL   | 80000   ← subtotal for IT
HR         | Admin  | 40000
HR         | NULL   | 40000   ← subtotal for HR
NULL       | NULL   | 120000  ← grand total
```

---

## 📌 ROLLUP — Hierarchical Subtotals

> `ROLLUP` creates subtotals that follow a **hierarchy**, from most
> detailed → up to a grand total. Order of columns in `ROLLUP` matters.

```sql
-- Syntax
SELECT Col1, Col2, AGG_FUNC(Col3)
FROM TableName
GROUP BY ROLLUP (Col1, Col2);
```

```sql
-- Example: Salary rollup by Department, then Role
SELECT
    Department,
    Role,
    SUM(Salary) AS TotalSalary
FROM Employees
GROUP BY ROLLUP (Department, Role);
```

**Result includes:**

1. Detail rows: Department + Role combo → `SUM(Salary)`
2. Subtotal rows: Department only (Role = `NULL`) → total per department
3. Grand total row: Department = `NULL`, Role = `NULL` → total for everything

```
Department | Role   | TotalSalary
──────────────────────────────────
IT         | Admin  | 50000
IT         | User   | 30000
IT         | NULL   | 80000     ← IT subtotal
HR         | Admin  | 40000
HR         | NULL   | 40000     ← HR subtotal
NULL       | NULL   | 120000    ← grand total
```

> 🔑 **Column order matters in ROLLUP** — it builds subtotals from
> right to left. `ROLLUP(Department, Role)` gives Department subtotals.
> `ROLLUP(Role, Department)` would give Role subtotals instead.

---

## 📌 CUBE — Every Possible Combination

> `CUBE` generates subtotals for **every combination** of the grouped
> columns — not just a hierarchy like ROLLUP.

```sql
-- Syntax
SELECT Col1, Col2, AGG_FUNC(Col3)
FROM TableName
GROUP BY CUBE (Col1, Col2);
```

```sql
-- Example: Same data, but CUBE instead of ROLLUP
SELECT
    Department,
    Role,
    SUM(Salary) AS TotalSalary
FROM Employees
GROUP BY CUBE (Department, Role);
```

**Result includes everything ROLLUP gives, PLUS:**

- Subtotal per **Role** across all departments (which ROLLUP does NOT give)

```
Department | Role   | TotalSalary
──────────────────────────────────
IT         | Admin  | 50000
IT         | User   | 30000
IT         | NULL   | 80000     ← IT subtotal
HR         | Admin  | 40000
HR         | NULL   | 40000     ← HR subtotal
NULL       | Admin  | 90000     ← Admin subtotal (across all depts) — CUBE only!
NULL       | User   | 30000     ← User subtotal (across all depts) — CUBE only!
NULL       | NULL   | 120000    ← grand total
```

---

## 📌 ROLLUP vs CUBE — Side by Side

|                                       | ROLLUP                                                   | CUBE                                                      |
| ------------------------------------- | -------------------------------------------------------- | --------------------------------------------------------- |
| Subtotal pattern                      | Hierarchical (one direction)                             | All possible combinations                                 |
| Column order matters                  | ✅ Yes — changes which subtotals appear                 | ❌ No — order doesn't change the set of subtotals        |
| Number of subtotal levels (2 columns) | 3 groupings (detail, dept-level, grand total)            | 4 groupings (detail, dept-level, role-level, grand total) |
| Use when                              | Data has a natural hierarchy (Region → Country → City) | You need every cross-combination of subtotals             |
| Performance                           | Faster (fewer combinations)                              | Slower (more combinations, more rows)                     |

## 📌 Identifying Subtotal Rows — GROUPING()

> `NULL` in the result could mean "this is a subtotal row" OR "the actual
> data value was NULL". `GROUPING()` tells them apart.

```sql
SELECT
    Department,
    Role,
    SUM(Salary) AS TotalSalary,
    GROUPING(Department) AS IsDeptSubtotal,
    GROUPING(Role)       AS IsRoleSubtotal
FROM Employees
GROUP BY ROLLUP (Department, Role);
```

| GROUPING(Col) value | Meaning                                                       |
| ------------------- | ------------------------------------------------------------- |
| `0`               | This is a real data value                                     |
| `1`               | This is a NULL generated by ROLLUP/CUBE (i.e. a subtotal row) |

```
Department | Role   | TotalSalary | IsDeptSubtotal | IsRoleSubtotal
IT         | Admin  | 50000       | 0              | 0
IT         | NULL   | 80000       | 0              | 1     ← Role NULL = subtotal
NULL       | NULL   | 120000      | 1              | 1     ← both = grand total
```

## 📌 Making Subtotal Rows Readable — GROUPING_ID / ISNULL

Replacing the `NULL` with a friendly label like `'All Roles'`:

```sql
SELECT
    ISNULL(Department, 'All Departments') AS Department,
    ISNULL(Role, 'All Roles')             AS Role,
    SUM(Salary) AS TotalSalary
FROM Employees
GROUP BY ROLLUP (Department, Role);
```

```
Department       | Role       | TotalSalary
IT               | Admin      | 50000
IT               | User       | 30000
IT               | All Roles  | 80000
All Departments  | All Roles  | 120000
```

> ⚠️ Only use `ISNULL` like this for display — if the actual data
> also contains real NULLs, use `GROUPING()` to distinguish them first
> (otherwise a real NULL row and a subtotal row look identical).

## 📌 Older Syntax You Might See (Legacy)

```sql
-- OLD (pre-2008) style — still works but deprecated, don't write new code like this
SELECT Department, Role, SUM(Salary)
FROM Employees
GROUP BY Department, Role WITH ROLLUP;

-- MODERN style — always prefer this
SELECT Department, Role, SUM(Salary)
FROM Employees
GROUP BY ROLLUP (Department, Role);
```

## 📌 Real-World Example — Sales Report

```sql
-- Monthly sales report: Region → Product, with subtotals and grand total
SELECT
    ISNULL(Region, 'All Regions')   AS Region,
    ISNULL(Product, 'All Products') AS Product,
    SUM(SaleAmount) AS TotalSales,
    COUNT(*)         AS OrderCount
FROM Sales
WHERE SaleDate >= '2026-01-01'
GROUP BY ROLLUP (Region, Product)
ORDER BY Region, Product;
```

> This single query replaces what would otherwise need a report query
> **plus** separate subtotal queries **plus** a grand total query.

## 📌 Quick Reference

| Goal                                     | Syntax                                |
| ---------------------------------------- | ------------------------------------- |
| Hierarchical subtotals + grand total     | `GROUP BY ROLLUP (Col1, Col2)`      |
| All combinations of subtotals            | `GROUP BY CUBE (Col1, Col2)`        |
| Tell subtotal rows apart from real NULLs | `GROUPING(ColName)` → 1 = subtotal |
| Friendly label instead of NULL           | `ISNULL(Col, 'All X')` in SELECT    |

## ❓ Interview Questions

**Q: What's the difference between ROLLUP and CUBE?**
A: ROLLUP produces hierarchical subtotals in one direction (based on column order), ending in a grand total. CUBE produces subtotals for every possible combination of the grouped columns, giving more subtotal rows than ROLLUP.

**Q: Why does column order matter in ROLLUP but not CUBE?**
A: ROLLUP builds subtotals progressively from the last column back to the first (right to left), so swapping column order changes which subtotal levels appear. CUBE generates all combinations regardless of order, so the result set is the same either way.

**Q: How do you distinguish a subtotal NULL from a real data NULL in ROLLUP/CUBE results?**
A: Use the `GROUPING(ColumnName)` function — it returns 1 if the NULL was generated by ROLLUP/CUBE as a subtotal marker, and 0 if it's an actual NULL value from the data.

**Q: When would you use ROLLUP over a manual UNION of separate aggregate queries?**
A: ROLLUP does it in a single pass over the data and a single query, which is both simpler to write and typically faster than running multiple GROUP BY queries and UNION-ing the results together.
