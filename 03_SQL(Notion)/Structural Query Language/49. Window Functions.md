
# 49.Window Functions

---

## 📌 What is a Window Function

> A **window function** performs a calculation **across a set of rows
> related to the current row** — without collapsing those rows into one,
> the way `GROUP BY` does.

```
GROUP BY:
──────────────────────────
Collapses many rows into ONE row per group.
5 rows in "IT" department → 1 output row for "IT"

Window Function (OVER):
──────────────────────────
Keeps ALL rows, adds a calculated column alongside each one.
5 rows in "IT" department → still 5 output rows, each with e.g. dept average attached
```

- Defined using the `OVER()` clause
- Doesn't reduce row count — every input row still appears in the output
- Used for: rankings, running totals, moving averages, comparing a row to its group

---

## 📌 Basic Syntax

```sql
SELECT
    Column1,
    Column2,
    WindowFunction() OVER (
        [PARTITION BY Column]     -- optional: splits into groups
        [ORDER BY Column]         -- optional: defines row order within partition
        [ROWS/RANGE frame]        -- optional: limits which rows are included
    ) AS ResultColumn
FROM TableName;
```

| Clause                      | Purpose                                                                           |
| --------------------------- | --------------------------------------------------------------------------------- |
| `PARTITION BY`            | Like GROUP BY, but doesn't collapse rows — restarts the calc per group           |
| `ORDER BY` (inside OVER)  | Row order for ranking/running functions — separate from the query's own ORDER BY |
| Frame (`ROWS BETWEEN...`) | Fine-tunes exactly which rows are included in the window                          |

## 📌 Ranking Functions — ROW_NUMBER, RANK, DENSE_RANK, NTILE

```sql
SELECT
    UserId,
    Department,
    Salary,
    ROW_NUMBER() OVER (ORDER BY Salary DESC)                    AS RowNum,
    RANK()       OVER (ORDER BY Salary DESC)                    AS Rnk,
    DENSE_RANK() OVER (ORDER BY Salary DESC)                    AS DenseRnk,
    NTILE(4)     OVER (ORDER BY Salary DESC)                    AS Quartile
FROM Employees;
```

**How ties are handled — the key difference:**

```
Salary   | ROW_NUMBER | RANK | DENSE_RANK
90000    | 1          | 1    | 1
90000    | 2          | 1    | 1      ← tie with above
80000    | 3          | 3    | 2      ← RANK skips to 3, DENSE_RANK doesn't
70000    | 4          | 4    | 3
```

| Function         | Ties get same number?                       | Skips numbers after a tie? |
| ---------------- | ------------------------------------------- | -------------------------- |
| `ROW_NUMBER()` | ❌ No — always unique, arbitrary tiebreak  | N/A                        |
| `RANK()`       | ✅ Yes                                      | ✅ Yes (leaves a gap)      |
| `DENSE_RANK()` | ✅ Yes                                      | ❌ No (no gap)             |
| `NTILE(n)`     | Splits rows into`n` roughly equal buckets | N/A                        |

## 📌 PARTITION BY — Ranking Within Groups

```sql
-- Rank employees by salary, SEPARATELY within each department
SELECT
    UserId,
    Department,
    Salary,
    RANK() OVER (PARTITION BY Department ORDER BY Salary DESC) AS DeptRank
FROM Employees;
```

```
UserId | Department | Salary | DeptRank
101    | IT         | 90000  | 1
102    | IT         | 80000  | 2
103    | IT         | 80000  | 2
201    | HR         | 60000  | 1     ← rank RESTARTS for HR
202    | HR         | 55000  | 2
```

> Without `PARTITION BY`, ranking would run across the **entire table**.
> With it, ranking **restarts** for each Department.

---

## 📌 Practical Example — Top N per Group

```sql
-- Get the TOP 2 highest-paid employees PER department
WITH RankedEmployees AS
(
    SELECT
        UserId, Department, Salary,
        ROW_NUMBER() OVER (PARTITION BY Department ORDER BY Salary DESC) AS RowNum
    FROM Employees
)
SELECT UserId, Department, Salary
FROM RankedEmployees
WHERE RowNum <= 2;
```

> 🔑 This is the **most common real-world use** of window functions —
> `TOP` alone can't do "top N per group", but `ROW_NUMBER() + PARTITION BY`
> can.

## 📌 Aggregate Window Functions — SUM, AVG, COUNT, MIN, MAX OVER()

> Regular aggregates collapse rows. The SAME functions used with `OVER()`
> **keep every row** and attach the aggregate value alongside it.

```sql
SELECT
    UserId,
    Department,
    Salary,
    SUM(Salary)   OVER (PARTITION BY Department)              AS DeptTotal,
    AVG(Salary)   OVER (PARTITION BY Department)              AS DeptAvg,
    Salary - AVG(Salary) OVER (PARTITION BY Department)       AS DiffFromAvg
FROM Employees;
```

```
UserId | Department | Salary | DeptTotal | DeptAvg | DiffFromAvg
101    | IT         | 90000  | 170000    | 85000   | 5000
102    | IT         | 80000  | 170000    | 85000   | -5000
201    | HR         | 60000  | 60000     | 60000   | 0
```

> No `GROUP BY` needed — every original row is kept, with the department's
> total/average attached to it.

## 📌 Running Totals — SUM() OVER with ORDER BY

```sql
-- Running total of daily sales
SELECT
    SaleDate,
    Amount,
    SUM(Amount) OVER (ORDER BY SaleDate) AS RunningTotal
FROM Sales
ORDER BY SaleDate;
```

```
SaleDate    | Amount | RunningTotal
2026-07-01  | 100    | 100
2026-07-02  | 150    | 250
2026-07-03  | 200    | 450
```

> Adding `ORDER BY` inside `OVER()` (without a frame) makes `SUM`
> accumulate row by row instead of totaling the whole partition at once.

## 📌 LAG and LEAD — Comparing to Previous/Next Row

```sql
SELECT
    SaleDate,
    Amount,
    LAG(Amount, 1)  OVER (ORDER BY SaleDate) AS PreviousDayAmount,
    LEAD(Amount, 1) OVER (ORDER BY SaleDate) AS NextDayAmount,
    Amount - LAG(Amount, 1) OVER (ORDER BY SaleDate) AS DayOverDayChange
FROM Sales
ORDER BY SaleDate;
```

| Function         | Looks at                                            | Common use                 |
| ---------------- | --------------------------------------------------- | -------------------------- |
| `LAG(col, n)`  | The row**n positions before** the current row | Compare to previous period |
| `LEAD(col, n)` | The row**n positions after** the current row  | Compare to next period     |

```sql
-- LAG/LEAD default to NULL when there's no previous/next row —
-- give a default value as the 3rd argument
LAG(Amount, 1, 0) OVER (ORDER BY SaleDate) AS PreviousDayAmount
```

## 📌 FIRST_VALUE and LAST_VALUE

```sql
SELECT
    UserId, Department, Salary,
    FIRST_VALUE(UserId) OVER (PARTITION BY Department ORDER BY Salary DESC) AS TopEarnerInDept
FROM Employees;
```

> ⚠️ `LAST_VALUE` needs an explicit frame (`ROWS BETWEEN ... AND ...`)
> to work as expected — by default the "window" only extends to the
> current row, so `LAST_VALUE` often returns the current row itself
> unless you specify:
> `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`

```sql
SELECT
    UserId, Department, Salary,
    LAST_VALUE(UserId) OVER (
        PARTITION BY Department
        ORDER BY Salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS LowestEarnerInDept
FROM Employees;
```

## 📌 Quick Reference — All Window Functions

| Function                                   | What it does                                      |
| ------------------------------------------ | ------------------------------------------------- |
| `ROW_NUMBER()`                           | Unique sequential number, ties broken arbitrarily |
| `RANK()`                                 | Rank with gaps after ties                         |
| `DENSE_RANK()`                           | Rank with no gaps after ties                      |
| `NTILE(n)`                               | Splits rows into n buckets                        |
| `SUM()/AVG()/COUNT()/MIN()/MAX() OVER()` | Aggregate without collapsing rows                 |
| `LAG(col, n)`                            | Value from n rows before                          |
| `LEAD(col, n)`                           | Value from n rows after                           |
| `FIRST_VALUE(col)`                       | First value in the window                         |
| `LAST_VALUE(col)`                        | Last value in the window (needs explicit frame)   |

## ❓ Interview Questions

**Q: What's the difference between GROUP BY and a window function?**
A: GROUP BY collapses multiple rows into one row per group. A window function (using OVER) performs the calculation across a related set of rows but keeps every original row in the output, adding the result as an extra column.

**Q: What's the difference between RANK() and DENSE_RANK()?**
A: Both give tied rows the same rank number, but RANK() leaves a gap in the numbering after a tie (e.g. 1, 1, 3), while DENSE_RANK() continues with no gap (e.g. 1, 1, 2).

**Q: How would you get the top 3 highest-paid employees per department?**
A: Use `ROW_NUMBER() OVER (PARTITION BY Department ORDER BY Salary DESC)` inside a CTE or subquery, then filter the outer query `WHERE RowNum <= 3` — TOP alone can't restart per group, but PARTITION BY can.

**Q: What do LAG and LEAD do?**
A: LAG retrieves a value from a row a specified number of positions before the current row (within the window's order), and LEAD retrieves a value from a row a specified number of positions after it — both commonly used for period-over-period comparisons.
