
# 43.DROP and TRUNCATE

---

## 📌 Overview

Two commands for removing things in SQL Server — but they work very differently.

> **DROP** → removes the **structure** (the table itself ceases to exist)
> **TRUNCATE** → removes all **data** inside the table (structure stays)

```
Your Table = A Box with Items inside
─────────────────────────────────────────────────────
TRUNCATE  →  empties the box       (box still exists, refillable)
DROP      →  destroys the box      (box gone — nothing left)
DELETE    →  removes items one by one (box stays, items gone row-by-row)
```

---

## 📌 DROP — Removing Structure

### DROP TABLE

> Permanently removes the entire table including its structure, all data,
> all indexes, and all constraints. Cannot be undone.

```sql
-- Syntax
DROP TABLE TableName;

-- Example
DROP TABLE TempUsers;

-- Drop if it exists (safer — no error if table doesn't exist)
DROP TABLE IF EXISTS TempUsers;

-- Drop multiple tables at once
DROP TABLE Table1, Table2, Table3;
```

> ⚠️ **Cannot DROP a table if:**
>
> - Another table has a FOREIGN KEY pointing to it
> - You must DROP the child table (or the FK constraint) first

```sql
-- ❌ WILL FAIL — Orders has FK to Users
DROP TABLE Users;
-- Error: Cannot drop table 'Users' because it is referenced by FOREIGN KEY constraint...

-- ✅ CORRECT — drop child first, then parent
DROP TABLE Orders;   -- or: ALTER TABLE Orders DROP CONSTRAINT FK_Orders_Users
DROP TABLE Users;
```

---

### DROP DATABASE

```sql
-- Remove an entire database (all tables, SPs, views, data)
DROP DATABASE LoginDB;

-- Safe version
DROP DATABASE IF EXISTS LoginDB;
```

> ⚠️ You cannot drop a database if someone is currently connected to it.

---

### DROP other objects

```sql
-- Drop a View
DROP VIEW IF EXISTS vw_ActiveUsers;

-- Drop a Stored Procedure
DROP PROCEDURE IF EXISTS sp_ValidateLogin;

-- Drop a Function
DROP FUNCTION IF EXISTS fn_GetUserRole;

-- Drop an Index
DROP INDEX IX_Users_Email ON Users;

-- Drop a Constraint (via ALTER TABLE)
ALTER TABLE Users
DROP CONSTRAINT UQ_Users_Email;
```

## 📌 TRUNCATE — Removing All Data

> **TRUNCATE TABLE** removes **all rows** from a table instantly,
> but keeps the table structure, columns, constraints, and indexes intact.

```sql
-- Syntax
TRUNCATE TABLE TableName;

-- Example
TRUNCATE TABLE LoginAttempts;    -- removes all rows, table structure stays

-- After truncate: table is empty but still exists
SELECT COUNT(*) FROM LoginAttempts;   -- returns 0
SP_HELP LoginAttempts;                -- still shows all columns
```

## 📌 TRUNCATE vs DELETE — The Critical Difference

> This is the **most common interview question** in SQL.

|                           | TRUNCATE                              | DELETE                                |
| ------------------------- | ------------------------------------- | ------------------------------------- |
| **What it removes** | ALL rows (no condition possible)      | All or specific rows (WHERE clause)   |
| **WHERE clause**    | ❌ Not allowed                        | ✅ Allowed                            |
| **Speed**           | ⚡ Very fast (minimal logging)        | 🐢 Slower (logs each row)             |
| **Transaction log** | Logs only page deallocations          | Logs every single row deleted         |
| **ROLLBACK**        | ✅ Can rollback if inside transaction | ✅ Can rollback if inside transaction |
| **Triggers**        | ❌ Does NOT fire DELETE triggers      | ✅ Fires DELETE triggers              |
| **IDENTITY reset**  | ✅ Resets to seed (back to 1)         | ❌ Does NOT reset identity            |
| **Foreign Key**     | ❌ Cannot truncate if FK exists       | ✅ Can delete if FK conditions met    |
| **Permission**      | Needs ALTER permission                | Needs DELETE permission               |

### Identity Reset Example

```sql
CREATE TABLE TestTable
(
    Id   INT IDENTITY(1,1) PRIMARY KEY,
    Name NVARCHAR(50)
);

INSERT INTO TestTable (Name) VALUES ('Sumit'), ('Rahul'), ('Priya');
-- Ids: 1, 2, 3

DELETE FROM TestTable;
INSERT INTO TestTable (Name) VALUES ('New');
SELECT * FROM TestTable;
-- Id = 4  ← DELETE did NOT reset identity

TRUNCATE TABLE TestTable;
INSERT INTO TestTable (Name) VALUES ('New');
SELECT * FROM TestTable;
-- Id = 1  ← TRUNCATE reset identity back to 1
```

## 📌 DROP vs TRUNCATE vs DELETE — The Big Three

> This full comparison is what interviewers always ask.

|                             | DROP                      | TRUNCATE                 | DELETE               |
| --------------------------- | ------------------------- | ------------------------ | -------------------- |
| **Category**          | DDL                       | DDL                      | DML                  |
| **Removes**           | Entire table + data       | All data only            | Specific rows        |
| **Structure stays**   | ❌ Gone                   | ✅ Stays                 | ✅ Stays             |
| **WHERE clause**      | ❌ N/A                    | ❌ Not allowed           | ✅ Allowed           |
| **Speed**             | Instant                   | Very fast                | Slow (row by row)    |
| **Transaction log**   | Minimal                   | Minimal                  | Full row logging     |
| **Rollback possible** | ❌ No (outside txn)       | ✅ If in transaction     | ✅ If in transaction |
| **Triggers**          | ❌ No                     | ❌ No                    | ✅ Yes               |
| **Identity reset**    | ❌ N/A (table gone)       | ✅ Yes                   | ❌ No                |
| **FK constraint**     | ❌ Cannot (if referenced) | ❌ Cannot (if FK exists) | ✅ Possible          |

## 📌 When to Use Which

```
Use DROP when:
────────────────────────────────────────────────
→ You want to completely remove a table (temp tables, test tables)
→ Restructuring the database schema
→ "I never want this table again"

Use TRUNCATE when:
────────────────────────────────────────────────
→ You want to empty a table completely and refill it
→ Clearing staging/temp data tables
→ Resetting log tables or audit tables at start of month
→ "Empty the table fast, keep the structure"

Use DELETE when:
────────────────────────────────────────────────
→ You want to remove specific rows (WHERE condition)
→ You need DELETE triggers to fire
→ "Remove rows where IsLocked = 1"
→ "Remove orders older than 2 years"
```

## 📌 Real-World Examples

### Scenario 1 — Clearing a staging table before reload

```sql
-- Every Monday, reload fresh data into StagingEmployees
TRUNCATE TABLE StagingEmployees;    -- fast, clears everything

INSERT INTO StagingEmployees
SELECT * FROM ExternalHRSystem;     -- refill with fresh data
```

### Scenario 2 — Dropping temp tables after a stored procedure

```sql
-- Inside a stored procedure
CREATE TABLE #TempResults (UserId NVARCHAR(50), Score INT);

-- ... do calculations, insert into temp table ...

-- Clean up at end
DROP TABLE IF EXISTS #TempResults;
```

### Scenario 3 — Delete specific rows (cannot use truncate)

```sql
-- Remove all locked users who haven't logged in for 1 year
DELETE FROM Users
WHERE IsLocked = 1
  AND LastLoginAt < DATEADD(YEAR, -1, GETDATE());

-- This is DELETE (not truncate) because we have a WHERE condition
```

### Scenario 4 — Drop table with foreign key (correct order)

```sql
-- Users → Orders relationship (Orders has FK to Users)
-- Goal: drop both tables

-- ❌ WRONG — Users is parent, cannot drop first
DROP TABLE Users;

-- ✅ CORRECT — drop child first
DROP TABLE IF EXISTS Orders;
DROP TABLE IF EXISTS Users;
```

## 📌 TRUNCATE and Transactions

Even though TRUNCATE is DDL, in SQL Server it **can be rolled back**
if it's inside an explicit transaction.

```sql
BEGIN TRANSACTION;

    TRUNCATE TABLE LoginAttempts;   -- removes all rows

    -- Oops! We didn't mean to do that
ROLLBACK TRANSACTION;

-- LoginAttempts data is restored
SELECT COUNT(*) FROM LoginAttempts;   -- data is back
```

> Note: This is SQL Server specific. In some other databases (like MySQL),
> TRUNCATE causes an implicit commit and cannot be rolled back.

## ❓ Interview Questions

**Q: What is the difference between DELETE and TRUNCATE?**
A: DELETE removes rows one by one with full logging and supports WHERE clause. TRUNCATE removes all rows with minimal logging, is much faster, resets identity, but doesn't support WHERE or fire triggers.

**Q: Can TRUNCATE be rolled back?**
A: Yes, in SQL Server — if TRUNCATE is inside an explicit `BEGIN TRANSACTION`, it can be rolled back. Outside a transaction it cannot be undone.

**Q: Why can't you TRUNCATE a table that has a foreign key?**
A: SQL Server checks referential integrity. If another table has an FK pointing to this table, truncating might leave orphan records in the child table. You must either drop the FK constraint or use DELETE instead.

**Q: What happens to IDENTITY after TRUNCATE vs DELETE?**
A: TRUNCATE resets the identity counter back to the seed value (usually 1). DELETE does NOT reset the counter — next insert continues from where it left off.

**Q: DROP TABLE vs TRUNCATE TABLE?**
A: DROP removes the entire table including structure. TRUNCATE only removes all data — structure, columns, constraints, indexes all remain.
