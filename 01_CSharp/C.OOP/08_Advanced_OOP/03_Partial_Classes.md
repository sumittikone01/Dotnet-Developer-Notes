# 🧩 Partial Classes

## 📌 What is it?

> `partial` allows a **single class definition to be split across multiple files**. At compile-time, the compiler merges all parts into one class.

---

## 🤔 Why do we need it?

- **Auto-generated code separation** — keep designer/generated code separate from your hand-written code (classic example: Windows Forms designer files)
- **Large class organization** — split a huge class logically across files (e.g., one file per concern)
- **Team collaboration** — multiple developers can work on different parts of the same class without merge conflicts

---

## 💻 Code Examples

**Basic — splitting across two files:**

```csharp
// File: Employee.Core.cs
public partial class Employee
{
    public string Name;
    public decimal Salary;
}

// File: Employee.Validation.cs
public partial class Employee
{
    public bool IsValid() => !string.IsNullOrEmpty(Name) && Salary > 0;
}

// Compiler merges both into ONE Employee class
var emp = new Employee { Name = "Sumit", Salary = 50000 };
Console.WriteLine(emp.IsValid());  // true — works as if it were one file
```

**Practical — real-world scenario (ASP.NET Core scaffolding/generated code pattern):**

```csharp
// File: OrderModel.cs (your hand-written business logic)
public partial class OrderModel
{
    public decimal CalculateTotal() => Quantity * UnitPrice;
}

// File: OrderModel.Generated.cs (auto-generated by a tool, e.g., from a database schema)
public partial class OrderModel
{
    public int Id { get; set; }
    public int Quantity { get; set; }
    public decimal UnitPrice { get; set; }
}
```

> 💡 This pattern shows up in scaffolded EF Core entity classes, Windows Forms designer files, and some code-generation tools — keeping generated code separate from custom logic prevents your changes from being overwritten when code is regenerated.

## ⚙️ Rules

| Rule                                                | Detail                                                                                            |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| All parts must use`partial` keyword               | Every file's class declaration needs`partial class ClassName`                                   |
| Must be same assembly                               | All parts must be compiled together, in the same project                                          |
| Access modifiers must be consistent (or compatible) | Can't have conflicting modifiers across parts                                                     |
| Partial methods also exist                          | Methods can be declared in one part and optionally implemented in another (advanced, less common) |

---

## 🚨 Common Mistakes

- ❌ Forgetting the `partial` keyword on ALL files defining pieces of the class — must be on every part
- ❌ Overusing partial classes to avoid properly organizing code — splitting for the sake of splitting reduces cohesion; use it for genuine reasons (generated code separation, large legacy class refactoring)
- ❌ Defining the same member in multiple partial files — causes a compile error (duplicate definition)

## 🎤 Interview Questions

| Question                                               | Key Point                                                                                       |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| What is a partial class?                               | A class whose definition is split across multiple files, merged by the compiler at compile-time |
| Why would you use partial classes?                     | Separating auto-generated code from hand-written code, or organizing very large classes         |
| Do partial class parts need to be in the same project? | Yes — same assembly, compiled together                                                         |
